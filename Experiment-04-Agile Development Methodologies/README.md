# Experiment 04 – Agile Development Methodologies Implementation

## Aim
To implement and compare different Agile Development Methodologies (Scrum, Kanban, and Extreme Programming) by developing a small software project and analyzing their workflow, productivity, and effectiveness.

## Objectives
- Understand Agile software development principles.
- Differentiate between Scrum, Kanban, and XP methodologies.
- Implement a small project using Agile practices.
- Compare Agile methodologies based on productivity and flexibility.
- Analyze advantages and limitations of each methodology.

---

## Theory

### Agile Development
Agile is an iterative and incremental software development methodology that focuses on:
- Customer collaboration
- Continuous feedback
- Rapid delivery
- Adaptive planning
- Frequent software releases

### Agile Manifesto
1. Individuals and interactions over processes and tools
2. Working software over comprehensive documentation
3. Customer collaboration over contract negotiation
4. Responding to change over following a plan

---

## Implementation

### Scrum
**Definition:** A sprint‑based framework with defined roles (Product Owner, Scrum Master, Development Team).
- Product Backlog: Login, Registration, Add Student, Delete, Search, Report
- Sprint‑1: Registration, Login, Add Student
- Sprint‑2: Search, Delete, Report
- Daily Scrum: “Yesterday, Today, Issues” format
- Sprint Review & Retrospective: Customer checks modules, team discusses improvements

---

### Kanban
**Definition:** A visual methodology emphasizing continuous delivery and limiting work‑in‑progress.
- Board Columns: To Do → In Progress → Testing → Completed
- Example tasks: Registration, Login, Add Student, Delete, Search
- Tasks move across columns until completion

---

### Extreme Programming (XP)
**Definition:** A methodology emphasizing software quality and customer satisfaction.
- Practices: Pair Programming, Test Driven Development (TDD), Continuous Integration, Refactoring, Small Releases
- Example: Write test for Login → Develop code → Run test → Pass → Commit → Deploy

## 📊 Agile Workflows

### Scrum Workflow
Customer Requirements  
↓  
Product Backlog  
↓  
Sprint Planning  
↓  
Sprint Backlog  
↓  
Development  
↓  
Daily Scrum  
↓  
Sprint Review  
↓  
Sprint Retrospective  
↓  
Product Increment

---

### Kanban Workflow
To Do → In Progress → Testing → Completed

Example:
- To Do: Registration, Login, Add Student, Delete, Search
- In Progress: Reports
- Completed: Home Page, Registration, Login

---

### XP Workflow
Pair Programming → Coding & Reviewing  
↓  
Test Driven Development (Write Test → Develop Code → Run Test → Pass)  
↓  
Continuous Integration (Code → Commit → Build → Test → Deploy)

## Comparison of Agile Methodologies
| Parameter           | Scrum        | Kanban       | XP             |
|---------------------|--------------|--------------|----------------|
| Development Cycle   | Sprint       | Continuous   | Iterative      |
| Team Size           | Medium-Large | Any          | Small          |
| Planning            | Sprint-based | Continuous   | Iterative      |
| Customer Feedback   | End of Sprint| Continuous   | Continuous     |
| Flexibility         | High         | Very High    | High           |
| Documentation       | Moderate     | Minimal      | Minimal        |
| Best Suitable For   | Large Projects| Maintenance | Small Projects |
| Meetings            | Daily Scrum  | Optional     | Frequent Comm. |
| Testing             | During Sprint| Continuous   | TDD            |
| Delivery            | Sprint End   | Anytime      | Small Releases |

---

## Result
Successfully implemented and compared Scrum, Kanban, and XP methodologies.  
All three support iterative software development but differ in workflow and management style.
- Scrum: Best for structured, larger projects.
- Kanban: Best for continuous maintenance and flexible workflows.
- XP: Best for small teams focusing on quality and rapid feedback.

---

## 🔑 Key Takeaways
- Agile methodologies prioritize adaptability, collaboration, and continuous delivery.
- **Scrum** is ideal for structured projects with defined sprints and roles.
- **Kanban** suits ongoing work and maintenance with flexible task flow.
- **XP** emphasizes quality through practices like TDD and pair programming.
- Choosing the right methodology depends on project size, complexity, and team dynamics.
